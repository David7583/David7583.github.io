AI 能调用工具之后，谁决定它可以做什么？Once AI can use tools, who decides what it may do?

把工具放进聊天框还不够。能力需要被发现、连接和配置；执行需要受权限约束，结果需要能够追溯。Putting tools inside a chat window is only a start. Capabilities need discovery, connections and configuration; execution needs permission boundaries and inspectable results.

工程方法Engineering approach

保留资源、工具、适配器和规范中心等管理框架。节点定义、工作流实例和运行状态分离；用明确的端口和参数契约组织数据流。Retain a management framework for resources, tools, adapters and governance. Separate capability definitions, workflow instances and run state; organize data flow through explicit ports and parameter contracts.

已经实现与验证Implemented and demonstrated

展示的五节点流程使用虚构家庭资料，依次完成数据输入、年份筛选、字段提取、文本模板和结果输出。画面来自实际运行，不代表通用 PDF 或 OCR 处理已经实现。The five-node example uses fictional family records: data input, year filtering, field extraction, a text template and result output. This is an actual run, not evidence of general PDF or OCR support.

范围与限制SCOPE & LIMITATIONS

公开源码默认只加载聊天，保留基础管理框架。Windows x64 已有启动验证；其他平台未验证。外部工具与模型需自行配置，远程服务会接收获准发送的请求。The public source loads chat by default and retains the management framework. Startup has been validated on Windows x64; other platforms are unverified. External tools and models need configuration. Remote services receive requests authorized by the user.
